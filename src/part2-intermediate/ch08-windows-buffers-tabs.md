# Chapter 8: 창, 버퍼, 탭

Neovim으로 실제 프로젝트를 작업하면 여러 파일을 동시에 다뤄야 한다. 이때 Neovim의 세 가지 핵심 개념 -- 버퍼(buffer), 창(window), 탭 페이지(tab page) -- 를 이해하는 것이 중요하다.

이 세 개념은 다른 편집기의 "파일", "창", "탭"과 비슷해 보이지만, 실제로는 상당히 다르다. 이 차이를 이해하면 멀티 파일 편집이 훨씬 효율적이 된다.

## 버퍼: 파일의 메모리 표현

### 버퍼란 무엇인가

버퍼(buffer)는 **파일의 내용을 메모리에 올린 것**이다. 파일을 열면 Neovim은 그 내용을 버퍼에 읽어 들이고, 우리는 버퍼를 편집하는 것이다. `:w`로 저장하면 버퍼의 내용이 파일에 기록된다.

핵심은 이것이다: **버퍼를 화면에서 보이지 않게 해도, 버퍼는 사라지지 않는다.** 다른 편집기에서 탭을 닫으면 파일이 닫히지만, Neovim에서 창을 닫아도 버퍼는 메모리에 남아 있다.

### 버퍼 목록 확인

```vim
:ls               " 열려 있는 버퍼 목록
:buffers           " :ls와 동일
```

출력 예시:

```
  1 %a   "main.js"                 line 42
  2 #h   "utils.js"                line 1
  3  h   "config.json"             line 15
```

각 항목의 의미:

| 기호 | 의미 |
|------|------|
| `%` | 현재 창에 표시 중인 버퍼 (current) |
| `#` | 이전 버퍼 (alternate) - `<C-^>`로 전환 |
| `a` | 활성 버퍼 (active) - 화면에 보이는 상태 |
| `h` | 숨겨진 버퍼 (hidden) - 화면에 보이지 않는 상태 |
| `+` | 수정됨 (modified) |

### 버퍼 전환

| 명령 | 동작 |
|------|------|
| `:b {number}` | 번호로 버퍼 전환 (예: `:b 3`) |
| `:b {name}` | 이름으로 버퍼 전환 (부분 매칭 가능, 예: `:b main`) |
| `:bnext` 또는 `:bn` | 다음 버퍼 |
| `:bprev` 또는 `:bp` | 이전 버퍼 |
| `:bfirst` | 첫 번째 버퍼 |
| `:blast` | 마지막 버퍼 |
| `<C-^>` 또는 `<C-6>` | 이전 버퍼(`#`)와 현재 버퍼를 토글 |

`:b` 명령에서 이름은 부분 매칭이 가능하다. `utils.js`를 열고 싶으면 `:b util`만 입력해도 된다. 단, 여러 버퍼가 매칭되면 에러가 발생하므로 좀 더 구체적으로 입력한다.

> **팁**: `<C-^>`는 두 파일을 번갈아 편집할 때 매우 유용하다. 소스 파일과 테스트 파일을 오갈 때 특히 좋다.

### 버퍼 삭제

```vim
:bd                " 현재 버퍼 삭제 (buffer delete)
:bd 3              " 3번 버퍼 삭제
:bd main.js        " 이름으로 삭제
:%bd               " 모든 버퍼 삭제
```

`:bd`는 버퍼를 목록에서 제거한다. 수정된 내용이 있으면 경고가 뜨고, `:bd!`로 강제 삭제할 수 있다.

### hidden 옵션

기본적으로 Neovim은 수정된 버퍼가 화면에 보이지 않게 되는 것을 허용하지 않는다. 저장하지 않은 채 다른 버퍼로 전환하려고 하면 에러가 발생한다.

```lua
-- init.lua에 추가
vim.opt.hidden = true
```

`hidden` 옵션을 켜면 저장하지 않은 버퍼도 숨길 수 있다. 여러 파일을 자유롭게 오가며 작업할 때 필수적인 옵션이다. Neovim에서는 기본적으로 활성화되어 있다.

## 창: 버퍼를 보는 뷰포트

### 창이란 무엇인가

창(window)은 **버퍼를 표시하는 뷰포트(viewport)**다. 하나의 버퍼를 여러 창에 동시에 표시할 수 있고, 하나의 창에는 항상 하나의 버퍼만 표시된다.

중요한 구분:

```
버퍼 = 파일의 내용 (메모리)
창   = 버퍼를 보는 시각적 영역 (화면)
```

같은 파일의 서로 다른 부분을 동시에 보고 싶으면, 같은 버퍼를 두 개의 창에 표시하면 된다. 한 창에서 편집하면 다른 창에도 즉시 반영된다.

### 창 분할

| 명령 | 동작 |
|------|------|
| `:split` 또는 `:sp` | 수평 분할 (위아래) |
| `:vsplit` 또는 `:vsp` | 수직 분할 (좌우) |
| `<C-w>s` | 수평 분할 (`:sp`와 동일) |
| `<C-w>v` | 수직 분할 (`:vsp`와 동일) |
| `:sp {file}` | 수평 분할 + 파일 열기 |
| `:vsp {file}` | 수직 분할 + 파일 열기 |
| `:new` | 수평 분할 + 새 빈 버퍼 |
| `:vnew` | 수직 분할 + 새 빈 버퍼 |

```
┌──────────────────────┐      ┌──────────┬───────────┐
│                      │      │          │           │
│      :sp 전          │  →   │  원래 창  │  (없음)   │
│                      │      ├──────────┤           │
│                      │      │  새 창    │           │
└──────────────────────┘      └──────────┴───────────┘

                              ┌──────────┬───────────┐
                              │          │           │
                        →     │  원래 창  │  새 창     │
                              │          │           │
                              └──────────┴───────────┘
                                    :vsp
```

### 창 간 이동

| 명령 | 동작 |
|------|------|
| `<C-w>h` | 왼쪽 창으로 이동 |
| `<C-w>j` | 아래 창으로 이동 |
| `<C-w>k` | 위 창으로 이동 |
| `<C-w>l` | 오른쪽 창으로 이동 |
| `<C-w>w` | 다음 창으로 순환 이동 |
| `<C-w>W` | 이전 창으로 순환 이동 |
| `<C-w>p` | 이전에 있던 창으로 이동 |

`<C-w>h/j/k/l`은 Normal 모드의 이동 키(`h/j/k/l`)와 동일한 방향이라 직관적이다.

> **팁**: 창 이동을 자주 한다면 키맵을 설정하면 편하다:
> ```lua
> -- init.lua에 추가
> vim.keymap.set('n', '<C-h>', '<C-w>h')
> vim.keymap.set('n', '<C-j>', '<C-w>j')
> vim.keymap.set('n', '<C-k>', '<C-w>k')
> vim.keymap.set('n', '<C-l>', '<C-w>l')
> ```

### 창 위치 교환

| 명령 | 동작 |
|------|------|
| `<C-w>H` | 현재 창을 화면 맨 왼쪽으로 이동 (수직 분할로 전환) |
| `<C-w>J` | 현재 창을 화면 맨 아래로 이동 (수평 분할로 전환) |
| `<C-w>K` | 현재 창을 화면 맨 위로 이동 (수평 분할로 전환) |
| `<C-w>L` | 현재 창을 화면 맨 오른쪽으로 이동 (수직 분할로 전환) |
| `<C-w>r` | 같은 행/열의 창들을 순환 교환 (rotate) |
| `<C-w>R` | 같은 행/열의 창들을 역순 순환 교환 |
| `<C-w>x` | 현재 창과 다음 창을 교환 (exchange) |

소문자 `h/j/k/l`은 "그 방향의 창으로 이동", 대문자 `H/J/K/L`은 "현재 창을 그 방향으로 보내기"로 기억하면 된다.

### 창 크기 조절

| 명령 | 동작 |
|------|------|
| `<C-w>=` | 모든 창 크기를 균등하게 |
| `<C-w>>` | 현재 창 너비 1 증가 |
| `<C-w><` | 현재 창 너비 1 감소 |
| `<C-w>+` | 현재 창 높이 1 증가 |
| `<C-w>-` | 현재 창 높이 1 감소 |
| `<C-w>\|` | 현재 창 너비를 최대로 |
| `<C-w>_` | 현재 창 높이를 최대로 |
| `{n}<C-w>\|` | 현재 창 너비를 n 열로 |
| `{n}<C-w>_` | 현재 창 높이를 n 행으로 |

숫자와 조합할 수 있다. `5<C-w>>`는 너비를 5만큼 증가시킨다.

### 창 닫기

| 명령 | 동작 |
|------|------|
| `:q` 또는 `<C-w>q` | 현재 창 닫기 (마지막 창이면 Neovim 종료) |
| `:close` 또는 `<C-w>c` | 현재 창 닫기 (마지막 창이면 닫지 않음) |
| `:only` 또는 `<C-w>o` | 현재 창만 남기고 나머지 닫기 |
| `:qa` | 모든 창 닫기 (Neovim 종료) |

`:q`와 `:close`의 차이: `:q`는 마지막 남은 창이면 Neovim을 종료하지만, `:close`는 마지막 창을 닫지 않는다. 실수로 Neovim을 종료하는 것을 방지하려면 `:close`를 습관화하면 좋다.

## 탭 페이지: 창 레이아웃의 모음

### 탭이란 무엇인가

Neovim의 탭 페이지(tab page)는 다른 편집기의 "탭"과 다르다. 다른 편집기에서 탭은 하나의 파일을 의미하지만, Neovim에서 탭은 **창 배치(layout)의 모음**이다.

```
다른 편집기:  탭 = 파일
Neovim:       탭 = 창들의 레이아웃
```

탭 하나에 여러 창이 있을 수 있고, 각 창은 서로 다른 버퍼를 표시할 수 있다.

### 탭 기본 조작

| 명령 | 동작 |
|------|------|
| `:tabnew` | 새 탭 생성 |
| `:tabnew {file}` | 새 탭에서 파일 열기 |
| `:tabnext` 또는 `gt` | 다음 탭 |
| `:tabprev` 또는 `gT` | 이전 탭 |
| `{n}gt` | n번째 탭으로 이동 (1부터 시작) |
| `:tabclose` | 현재 탭 닫기 |
| `:tabonly` | 현재 탭만 남기고 나머지 닫기 |
| `:tabmove {n}` | 현재 탭을 n번째 위치로 이동 |
| `:tabs` | 열려 있는 탭 목록 |

### 탭의 적절한 사용

탭을 "파일당 하나"로 사용하는 것은 Neovim의 의도와 맞지 않다. 탭은 다음과 같은 상황에 적합하다:

- **서로 다른 작업 컨텍스트 분리**: 프론트엔드 작업 탭, 백엔드 작업 탭
- **다른 프로젝트 디렉토리**: `:tabnew | :lcd /other/project`
- **임시 참조 레이아웃**: 문서를 참고하면서 코드를 작성하는 레이아웃
- **비교 작업**: diff를 위한 별도 탭

## 버퍼, 창, 탭의 관계

세 개념의 관계를 정리하면:

```
탭 페이지 1                    탭 페이지 2
┌──────────────────────┐      ┌──────────────────────┐
│ ┌────────┬─────────┐ │      │ ┌──────────────────┐ │
│ │ 창 1   │ 창 2    │ │      │ │ 창 4             │ │
│ │ 버퍼A  │ 버퍼B   │ │      │ │ 버퍼A            │ │
│ ├────────┴─────────┤ │      │ ├──────────────────┤ │
│ │ 창 3             │ │      │ │ 창 5             │ │
│ │ 버퍼C            │ │      │ │ 버퍼D            │ │
│ └──────────────────┘ │      │ └──────────────────┘ │
└──────────────────────┘      └──────────────────────┘

버퍼 목록: A, B, C, D (모든 탭에서 공유)
```

핵심 원칙:

1. **버퍼**는 전역이다 -- 모든 탭과 창에서 공유된다
2. **창**은 탭 안에 존재한다 -- 탭을 닫으면 그 안의 창도 닫힌다
3. **탭**은 창 레이아웃을 저장한다 -- 파일이 아니라 배치를 관리한다

## 효율적인 멀티 파일 워크플로우

### 워크플로우 1: 버퍼 중심 (추천)

가장 많이 권장되는 방식이다. 창 하나에서 버퍼를 빠르게 전환한다:

1. `:e file1.js`, `:e file2.js`로 파일을 열어 버퍼에 로드
2. `:b file1`이나 `<C-^>`로 버퍼 간 전환
3. 필요할 때만 `:sp`나 `:vsp`로 화면 분할
4. 비교가 끝나면 `<C-w>o`로 단일 창으로 복귀

이 방식은 화면 공간을 최대한 활용하면서도 빠르게 파일을 전환할 수 있다.

### 워크플로우 2: 분할 창 고정

두세 개의 관련 파일을 나란히 놓고 작업하는 방식:

```
┌─────────────────┬─────────────────┐
│ component.tsx   │ component.css   │
│                 │                 │
│                 │                 │
├─────────────────┴─────────────────┤
│ component.test.tsx                │
└───────────────────────────────────┘
```

소스, 스타일, 테스트를 동시에 보면서 작업할 수 있다.

### 워크플로우 3: 탭으로 컨텍스트 분리

큰 프로젝트에서 여러 기능을 동시에 작업할 때:

- **탭 1**: 인증(auth) 관련 파일들
- **탭 2**: API 라우트 관련 파일들
- **탭 3**: 데이터베이스 마이그레이션

각 탭에서 해당 기능에 필요한 파일들을 창으로 분할하여 배치한다.

### 실전 명령 조합

자주 사용하는 명령 조합을 정리한다:

```vim
" 파일 열기와 분할
:e src/main.js                 " 현재 창에서 파일 열기
:vsp src/utils.js              " 수직 분할로 파일 열기
:sp test/main.test.js          " 수평 분할로 파일 열기

" 빠른 전환
<C-^>                          " 이전 버퍼와 토글
:b main                        " main이 포함된 버퍼로 전환

" 정리
<C-w>o                         " 현재 창만 남기기
:bd                            " 현재 버퍼 삭제

" 탭 활용
:tabnew %                      " 현재 버퍼를 새 탭에서 열기
gt / gT                        " 탭 간 이동
```

## 실습: 멀티 파일 편집 연습

다음 구조의 파일들을 만들고 연습해 보자:

```bash
mkdir -p practice/src practice/test
echo "export function add(a, b) { return a + b; }" > practice/src/math.js
echo "export function greet(name) { return 'Hello ' + name; }" > practice/src/utils.js
echo "import { add } from '../src/math.js';" > practice/test/math.test.js
echo '{ "name": "practice" }' > practice/config.json
```

```bash
nvim practice/src/math.js
```

연습 과제:

1. `:e practice/src/utils.js`로 두 번째 파일 열기 → `:ls`로 버퍼 목록 확인
2. `<C-^>`로 `math.js`와 `utils.js`를 번갈아 전환
3. `:vsp practice/test/math.test.js`로 수직 분할 → `<C-w>h`와 `<C-w>l`로 창 간 이동
4. `<C-w>=`로 창 크기 균등화 → `<C-w>>`를 5번 눌러 현재 창 확대
5. `<C-w>H`로 현재 창을 왼쪽으로 이동 → 레이아웃 변화 확인
6. `:tabnew practice/config.json`으로 새 탭 → `gT`로 이전 탭으로 복귀
7. `<C-w>o`로 현재 창만 남기기 → `:ls`로 버퍼들이 여전히 존재하는지 확인

## 핵심 정리

- **버퍼**는 파일의 메모리 표현이다 -- 창을 닫아도 사라지지 않는다
- **창**은 버퍼를 보는 뷰포트다 -- 같은 버퍼를 여러 창에 표시할 수 있다
- **탭 페이지**는 창 레이아웃의 모음이다 -- "파일당 하나의 탭"이 아니다
- **`<C-^>`**: 두 파일을 오갈 때 가장 빠른 방법
- **`:b {name}`**: 이름으로 버퍼를 빠르게 전환
- **`<C-w>s`/`<C-w>v`**: 수평/수직 분할
- **`<C-w>h/j/k/l`**: 창 간 이동, **`<C-w>H/J/K/L`**: 창 위치 변경
- **`<C-w>=`**: 모든 창 크기 균등화, **`<C-w>o`**: 현재 창만 남기기
- 버퍼 중심 워크플로우를 기본으로 하되, 필요에 따라 창 분할과 탭을 활용하라
